# 예약 화면 개선 및 구장별 공개 준비

이 변경은 로컬 작업본입니다. 운영 배포나 운영 Firestore 설정 변경은 수행하지 않았습니다.

## 준비된 구장

| 저장 키 | 표시 이름 | 코트 수 | 최초 회원 노출 |
| --- | --- | --- | --- |
| 국제 | 장유 국제테니스장 | 8 | 공개 |
| 능동 | 능동 테니스장 | 8 | 비공개 |
| 원도심 | 원도심 테니스장 | 4 | 비공개 |
| 동부 | 동부 테니스장 | 7 | 비공개 |

기존 저장 키를 유지하여 기존 예약 조회 경로를 바꾸지 않았습니다. 코트 수는 예약표와 관리자 단체대관 선택 목록에 함께 적용됩니다. 구장을 바꾸면 날짜는 유지하고 선택한 코트·시간은 초기화합니다.

## 나중에 구장을 공개하는 방법

디자인을 검토하고 별도로 운영 배포한 뒤, 관리자 설정의 **구장 공개 설정**에서 원하는 구장만 체크하고 **저장하기**를 누릅니다. 예를 들어 능동만 체크하면 국제와 능동만 회원 선택 목록에 표시됩니다. **추가 구장 전체 공개**로 일괄 선택할 수도 있습니다. 체크만 하고 저장하지 않으면 회원 공개 상태는 바뀌지 않습니다.

`settings/global.centerVisibility`에 각 구장의 불리언 값을 저장합니다. 국제는 항상 공개되고 다른 구장은 명시적인 `true` 값이 있어야 공개됩니다. 예전 `isCenterOpen` 값이 남아 있어도 신규 구장이 자동 공개되지 않습니다. 기존 필드는 전체 선택 상태와 함께 계속 저장합니다. 관리자는 공개 여부와 관계없이 모든 구장을 선택할 수 있고, 비공개 구장에는 미리보기 표시가 나타납니다.

이 설정은 앱 화면의 노출 제어입니다. 예약 저장·결제·환불 및 기존 요금 계산 구현은 변경하지 않았습니다. 구장별 요금 차등이나 자동 예약 오픈 시각 기능을 추가한 것은 아닙니다. 운영자가 원하는 시점에 설정을 저장하여 공개합니다. 이미 켜 둔 회원 화면에는 기존 설정 재조회 또는 새로고침 시 반영됩니다.

능동·동부·원도심은 제공받은 사진을 참고한 SVG 개략도를 사용합니다. 사무실 위치를 표시하고 능동만 확정된 1–8번 좌표를 사용합니다. 동부·원도심 번호는 미확정이므로 위치 강조를 하지 않습니다. 공개 산출물에 세 SVG 파일을 명시적으로 포함합니다.

## 디자인

딥그린과 밝은 회백색을 기본으로 사용합니다. 예약·입금대기·정기·선택 상태를 글자와 색상 범례로 구분합니다. 모바일에서도 전체 달력을 기본으로 표시하며 **달력접기/달력펼치기**로 직접 접을 수 있습니다. PC는 달력과 예약표를 나란히 배치합니다. 화면 높이에 맞춰 모든 코트 행이 세로 스크롤 없이 보이도록 표 높이를 조정합니다. 모바일 시간표는 좌우 이동을 지원합니다. 개발 환경의 날씨는 **테스트 예보**로 표시하는 가상 데이터이며, 운영의 실제 날씨 조회 경로는 유지합니다.

## 검증 및 화면 확인

```powershell
npm.cmd test
npm.cmd run test:design
npm.cmd run build:pages
```

`test:design`은 Chrome을 사용하고 모든 요청을 로컬 파일 또는 차단 응답으로 처리합니다. 실제 운영 사이트·Firebase·결제 서비스에 요청을 보내지 않습니다. 구장 공개 저장 검사는 메모리에서만 수행합니다. 차단된 초기 날씨·인증 요청의 `Failed to fetch`는 예상되는 결과이며 다른 페이지 오류는 실패로 처리합니다.

화면 캡처와 검사 결과는 `dev/artifacts/design-preview/`에 생성됩니다. 화면은 가상 상태이며 실제 예약 데이터가 아닙니다. 로컬 배포 파일은 `dist/`에 생성되며 빌드 명령은 업로드하지 않습니다.


## 2026-10-27 배포 준비

국제만 기본 공개합니다. 과거 centerVisibility 또는 isCenterOpen 값만으로 추가 구장이 공개되지 않도록 별도 확인 기록을 요구합니다. 운영 예약·결제·문자·설정 데이터는 배포 과정에서 변경하지 않습니다. 기존 알려진 결함은 dev/KNOWN-ISSUES.md에 남아 있습니다.
