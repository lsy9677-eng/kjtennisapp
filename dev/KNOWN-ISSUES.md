# 이번 작업에서 수정하지 않은 업무 로직

환경 분리와 개발 대역만 구현했다. 다음 문제는 운영 반영 여부·실제 피해 여부를 확인하지 않았으며 이번 변경에서 해결하지 않는다.

| 항목 | 현재 소스 동작 / 재현 | 향후 정상 동작 기준 |
| --- | --- | --- |
| 평일 요금 | `isWeekendOrHoliday`의 Promise를 참으로 평가하여 평일에도 주말 행 사용. 가상 행렬에서 월요일 주간 비시민 6000원, 야간 8000원으로 재현 | 평일은 평일 행 사용(같은 가상 행렬 기준 2000/4000원) |
| 계절 요금 | 야간 시작 경계는 적용하지만 결제 행렬은 계절 dayPrice/nightPrice 무시 | 운영 정책을 확정한 뒤 결제·환불·통계에서 일관되게 적용 |
| 환불 금액 | 현재 시민 여부·현재 요금표로 재계산. 가상 사용자의 시민 여부나 요금표 변경에 따라 환불액 변경 재현 | 결제 당시 실제 납부액과 할인 근거를 보존해 산정 |
| 일일 제한 동시성 | 서로 다른 슬롯에 대한 일일 제한 검사가 트랜잭션 밖에 있음. 같은 기존 3시간을 읽는 두 추가 3시간 검사가 모두 통과하는 단위 재현 | 동시 요청 전체를 합쳐 일일 제한을 보장 |
| 관리자/정기 충돌 | 관리자 batch.set은 기존 슬롯을 덮어쓸 수 있고 정기 규칙은 별도 임의 ID로 저장. 소스 확인만 실시 | 관리자·정기·일반 예약을 포함한 원자적 점유 보호 |
| 단체 대관 center | 예약 문서에 center 필드가 없어 센터별 조회에서 누락 가능. 소스 확인만 실시 | 저장·조회 스키마 일치 |
| 결제 후 저장 실패 | 결제 성공 후 saveBook 호출. 단위 테스트는 저장 거절을 주입해 호출 순서와 보상 호출 부재 확인 | 서버 결제 검증, 금액 대조, 멱등 처리, 저장 실패 복구/환불 |
| 결제 기록 | 일반 예약에 실제 납부액·단가·할인 근거 저장 없음. 소스 확인 | 불변의 결제 및 환불 근거 보존 |
| 날짜/시간대 | 브라우저 현지 시간과 UTC 날짜 문자열 혼용. 시간대별 경계값 실험은 미실시 | 업무 기준 Asia/Seoul과 날짜 경계를 일관되게 적용 |
| 취소/환불 | 회원 요청은 SMS 또는 게시글 작성. 관리자 삭제와 PG 환불 연결이 이 저장소에 없음 | 취소 상태와 실제 환불 처리 관계를 명시하고 검증 |
| reCAPTCHA | 기존 doPay는 검증 요청 예외 시 진행 허용. 이번에는 로컬 대역만 추가 | 별도 정책 검토 후 서버 검증 실패 처리 확정 |
| 권한 | localStorage.isAdm 기반 UI 권한 복원 존재. 운영 Rules 미확인 | 서버 권한 검증 확인 필요 |

`tests/characterization.test.mjs`는 **현재 결함이 유지되는 것을 통과 조건으로 삼는 재현 테스트**다. 결함 해결이나 정상 업무 규칙을 보장하지 않는다. 동시성 재현은 격리된 검사 함수의 단위 모델이며 실제 여러 클라이언트의 경합 테스트는 아니다.

`tests/expected-behavior.test.mjs`의 6개 TODO는 **미구현된 향후 정상 기준**이다. 테스트 러너의 TODO 출력은 통과로 보고하지 않는다.

## TODO 6개와 미수정 결함의 대응

| TODO | 미수정 결함 | 현재 근거 |
| --- | --- | --- |
| 1. 평일은 평일 요금 행 사용 | async 주말 판별을 await하지 않음 | 결함 재현 테스트 |
| 2. 계절 요금 일관 적용 | 계절 금액이 결제 행렬에서 무시됨 | 결함 재현 테스트 |
| 3. 원래 납부액 기준 환불 | 현재 요금/시민 상태로 재계산, 납부액 스냅샷 부재 | 결함 재현 + 저장 소스 확인 |
| 4. 동시 예약 일일 제한 | 제한 검사가 슬롯 트랜잭션 밖에 있음 | 격리된 함수 단위 경합 모델, 실제 다중 클라이언트 미검증 |
| 5. 관리자·정기 점유 보호 | batch.set 덮어쓰기 및 임의 ID 규칙 중복 | 소스 확인만 실시 |
| 6. 결제 검증과 실패 복구 | 클라이언트 성공 후 저장, 보상/서버 검증 부재 | 호출 순서 단위 모델 + 소스 확인, 실제 PG 미검증 |

환경/원본 보존 검사 통과는 위 TODO의 정상 동작을 입증하지 않는다. 단체 대관 center 누락, 날짜 혼용, 권한 문제 등 나머지 항목도 수정하지 않았다.
