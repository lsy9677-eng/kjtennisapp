# 수정 범위와 남은 업무 문제

환경 분리 후 사용자 요청으로 평일·주말 판정과 예약창의 계절 설정 로드 대기/실패 차단만 수정했다. 나머지 문제는 운영 발생 여부·피해 여부를 확인하지 않았으며 해결하지 않았다. 운영 금액 설정을 읽거나 변경하지 않았다.

## 정정된 요금 운영 기준과 분류

사용자가 확인한 현재 기준은 **평일·주말 금액 동일**, **계절 설정은 라이트 사용에 맞춘 야간 시작 시각 조정이 주목적**이다. 향후 금액은 달라질 수 있다. 운영 설정 문서나 실제 결제 내역은 읽지 않았다.

- **현재 금액 오류로 확인한 사항:** 없음. 이전의 평일·계절 요금 관련 표현은 현재 과금 오류가 확인된 것처럼 읽힐 수 있어 정정한다.
- **의도된 동작:** 평일·주말 행의 금액이 같은 것, 계절별 `nightStart`를 우선 적용하고 결제 단가는 기존 요금표에서 가져오는 것. 별도의 계절 금액 기능을 새로 만들 근거가 아니다.
- **표시/행 선택 수정 완료:** 주말 판별을 동기 반환으로 고쳐 평일·주말 요금표와 설명이 일치한다. 동일 요금의 금액은 그대로이며 상이한 가상 요금도 각각 적용된다.
- **로드 대기/실패 차단 완료:** 예약창은 기본 설정과 서버의 계절 설정을 기다린 뒤 계산한다. 로딩/실패 중에는 버튼과 직접 doPay 호출이 차단된다. 정상 빈 시즌과 읽기 실패를 구분한다.
- **남은 설정 혼선:** 계절·기본 단일 금액은 더치페이, 결제·환불·통계는 4행 요금표를 쓴다. 현재 각 설정값의 일치 여부는 미확인이다. 시즌 중복·역전 입력 검증도 이번 범위 밖이다.
- 소스 초기 요금표는 평일·주말이 다르다. 사용자 설명의 운영 요금표와 구분하며, 동일 금액일 때 오차가 없다는 판단은 해당 설정이 로드된 상태를 전제로 한다.

기존 관리자 설정 연결, 수정 전 조사와 현재 검증은 [PRICING-REVIEW.md](PRICING-REVIEW.md)에 기록했다. 계절 금액·더치페이·환불 산식·예약 동시성·PG 요청 본문과 서버 구조는 변경하지 않았다. 공용 날짜 판정의 수정은 공용 요금표 조회에도 적용된다.

| 항목 | 현재 소스 동작 / 재현 | 향후 정상 동작 기준 |
| --- | --- | --- |
| 평일·주말 요금 행 선택 — 수정 완료 | 동기 판정으로 요금 행/설명 일치. 가상 월요일 1000/3000원, 토요일 5000/7000원 각각 적용. 동일 설정은 금액 변화 없음 | 회귀 검사 통과. 기존 금액 설정값은 유지 |
| 계절 야간 시작 — 의도된 연결 | 기간별 `nightStart`가 기본 `nightStartHour`를 대체하고 해당 시각부터 야간 요금표 행 적용. 별도 계절 금액을 결제에 적용하지 않는 것을 현재 운영 의도상 과금 결함으로 단정하지 않음 | 라이트 시작 시각 조정이라는 기존 기능 유지. 별도 금액 정책을 임의 추가하지 않음 |
| 단일 금액/계절 금액 경로 — 설정 혼선 | 더치페이는 `getPriceForDate`의 dayPrice/nightPrice 사용, 결제·환불·통계는 4행 행렬 사용. 서로 다른 가상 값을 넣으면 결과 차이 발생 | 실제 설정값과 별도 금액 지원 정책 확인 필요. 현재 금액 오류로 확인된 것은 아님 |
| 시즌 로드 — 수정 완료 | 예약창에서 읽기 완료 후 계산. 실패 시 기존/기본값으로 결제하지 않음. 늦은 이전 응답·선택 변경도 차단 | 지연/실패/재시도 검사 통과. 빈 시즌 성공은 기본 시각 사용 |
| 시즌 입력 경계 — 남은 위험 | 양 끝 날짜 포함, 겹치면 배열 첫 항목 우선, 역전/겹침 저장 검사 없음 | 정상 비중첩 기간과 야간 시작 정각 검사 통과. 입력 정책 변경은 미실시 |
| 환불 금액 | 현재 시민 여부·현재 요금표로 재계산. 가상 사용자의 시민 여부나 요금표 변경에 따라 환불액 변경 재현 | 결제 당시 실제 납부액과 할인 근거를 보존해 산정 |
| 일일 제한 동시성 | 서로 다른 슬롯에 대한 일일 제한 검사가 트랜잭션 밖에 있음. 같은 기존 3시간을 읽는 두 추가 3시간 검사가 모두 통과하는 단위 재현 | 동시 요청 전체를 합쳐 일일 제한을 보장 |
| 관리자/정기 충돌 | 관리자 batch.set은 기존 슬롯을 덮어쓸 수 있고 정기 규칙은 별도 임의 ID로 저장. 소스 확인만 실시 | 관리자·정기·일반 예약을 포함한 원자적 점유 보호 |
| 단체 대관 center | 예약 문서에 center 필드가 없어 센터별 조회에서 누락 가능. 소스 확인만 실시 | 저장·조회 스키마 일치 |
| 결제 후 저장 실패 | 결제 성공 후 saveBook 호출. 단위 테스트는 저장 거절을 주입해 호출 순서와 보상 호출 부재 확인 | 서버 결제 검증, 금액 대조, 멱등 처리, 저장 실패 복구/환불 |
| 결제 기록 | 일반 예약에 실제 납부액·단가·할인 근거 저장 없음. 소스 확인 | 불변의 결제 및 환불 근거 보존 |
| 날짜/시간대 | 일반 날짜 처리에 현지 시간/UTC 문자열 혼용. 요금의 정규 날짜 문자열 시즌 경계와 자정 0시 분류는 가상 검사했으나 앱 전반의 시간대별 동작은 미검증 | 요금은 선택한 예약일 기준. 자정 이후 야간 연장·24시 날짜 이월은 현재 예약 UI 범위 밖이며 임의 정책을 추가하지 않음 |
| 취소/환불 | 회원 요청은 SMS 또는 게시글 작성. 관리자 삭제와 PG 환불 연결이 이 저장소에 없음 | 취소 상태와 실제 환불 처리 관계를 명시하고 검증 |
| reCAPTCHA | 기존 doPay는 검증 요청 예외 시 진행 허용. 이번에는 로컬 대역만 추가 | 별도 정책 검토 후 서버 검증 실패 처리 확정 |
| 권한 | localStorage.isAdm 기반 UI 권한 복원 존재. 운영 Rules 미확인 | 서버 권한 검증 확인 필요 |

`tests/characterization.test.mjs`는 **현재 계산 경로와 잠재 결함을 재현하는 테스트**다. 평일/계절 관련 통과를 현재 운영의 금액 오류나 결함 해결로 해석하지 않는다. 동시성 재현은 격리된 함수 단위 모델이며 실제 다중 클라이언트 경합 검사는 아니다. `tests/pricing-settings.test.mjs`는 동일/상이 요금·기존 설정 연결·시즌/자정 경계를 추가 확인한다.

평일 판정 TODO는 실제 회귀 검사로 전환했다. `tests/expected-behavior.test.mjs`의 남은 TODO **5개**는 미구현 기준 또는 정책 검토 항목이다. 계절 금액 항목은 강제 적용 요구가 아니라 표시 경로 일관성 검토다. TODO는 통과 수에 포함하지 않는다.

## 남은 TODO 5개와 미수정 결함의 대응

| TODO | 미수정 결함 | 현재 근거 |
| --- | --- | --- |
| 1. 별도 금액 경로의 정책·표시 일관성 검토 | 현재 의도는 야간 시각 조정. 더치페이와 결제의 금액 경로가 다르므로 설정/정책 확인 필요. 계절 금액 적용 기능을 임의로 추가하지 않음 | 기존 경로 재현, 운영 값 미확인 |
| 2. 원래 납부액 기준 환불 | 현재 요금/시민 상태로 재계산, 납부액 스냅샷 부재 | 결함 재현 + 저장 소스 확인 |
| 3. 동시 예약 일일 제한 | 제한 검사가 슬롯 트랜잭션 밖에 있음 | 격리된 함수 단위 경합 모델, 실제 다중 클라이언트 미검증 |
| 4. 관리자·정기 점유 보호 | batch.set 덮어쓰기 및 임의 ID 규칙 중복 | 소스 확인만 실시 |
| 5. 결제 검증과 실패 복구 | 클라이언트 성공 후 저장, 보상/서버 검증 부재 | 호출 순서 단위 모델 + 소스 확인, 실제 PG 미검증 |

환경/원본 보존 검사 통과는 위 TODO의 정상 동작을 입증하지 않는다. 단체 대관 center 누락, 날짜 혼용, 권한 문제 등 나머지 항목도 수정하지 않았다.
